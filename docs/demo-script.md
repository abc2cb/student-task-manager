# Сценарій демонстрації Student Task Manager (3–5 хвилин)

## 1. Вступ (0:00–0:40)

- **Продукт:** Student Task Manager — вебзастосунок, який збирає навчальні завдання з різних дисциплін в одному списку.
- **Проблема:** завдання записані в різних місцях (чат, папір, календар), через це губляться терміни й не видно загального обсягу роботи.
- **Користувач:** студент, який одночасно виконує роботи з кількох дисциплін.
- **Користь:** один список із дисципліною, терміном, пріоритетом і станом; пошук і фільтри; окремий обліковий запис для кожного студента.

## 2. Версія, яку демонструємо (0:40–1:00)

Демонструється **розширена версія після самостійної роботи**: серверна частина на `node:http`, база даних SQLite (`node:sqlite`), реєстрація, вхід із сесією в `HttpOnly`-cookie, ізоляція записів кожного користувача. Статичний MVP практичної роботи №16 (`app/`) залишено в репозиторії для історії; його можливості входять до розширеної версії.

## 3. Підготовка до показу (1:00–1:20)

```bash
cd server
npm run init-db     # лише для нової бази
npm start           # http://127.0.0.1:3000
```

У браузері відкрити <http://127.0.0.1:3000>. Якщо порт зайнятий — `PORT=3027 npm start` і та сама адреса з новим портом.

## 4. Послідовність дій (1:20–3:40)

1. **Реєстрація.** Вкладка «Реєстрація» → ім’я `Антон Бєлка`, адреса `anton@example.com`, пароль `Password123` → «Створити обліковий запис». Відкривається робочий екран із порожнім списком.
2. **Створення завдань.** Заповнити назву, опис, термін, пріоритет і дисципліну → «Додати завдання». Повторити для трьох завдань із тестових даних.
3. **Редагування.** «Редагувати» на картці «Практична робота №17 — фінальний пакет», змінити назву → «Зберегти зміни». Кількість записів у лічильнику «Усі» не змінюється — дублікат не створюється.
4. **Зміна стану.** «Позначити виконаним»: картка отримує стан «Виконано», лічильники стають 3/2/1; кнопка «Повернути до активних» працює в зворотний бік.
5. **Фільтри й пошук.** Фільтр «Стан → Виконані» показує лише виконане завдання. Далі пошук «практична» + пріоритет «Високий» — у списку один запис, тобто пошук і фільтри діють разом.
6. **Видалення.** «Видалити» на тестовому завданні «Прочитати розділ про тестування», підтвердити — зникає саме цей запис, лічильники 2/1/1.
7. **Ізоляція даних.** «Вийти» → зареєструвати другого користувача `maria@example.com` → її список порожній, чужих завдань не видно.
8. **Збереження даних (за потреби).** Зупинити сервер `Ctrl+C`, запустити `npm start` знову, увійти як `anton@example.com` — завдання на місці, бо вони зберігаються у файлі SQLite.

## 6. Очікуваний результат

- після реєстрації відкривається порожній список із повідомленням «Завдань ще немає…»;
- три завдання з’являються у списку з дисципліною, терміном, пріоритетом і станом;
- редагування змінює вибраний запис без дубліката;
- «Позначити виконаним» змінює стан і лічильники (3/2/1), повторне натискання повертає до активних;
- фільтр «Виконані» та пошук «практична» + високий пріоритет показують очікувані записи;
- видалення прибирає лише вибраний запис (2/1/1);
- другий користувач бачить порожній список і не має доступу до чужих записів (прямі запити → `404`);
- після перезапуску сервера дані залишаються.

## 7. Підсумок і відомі обмеження (3:40–4:30)

- реалізовано: облікові записи, CRUD завдань, зміна стану, пошук, три фільтри, шість режимів сортування, лічильники, збереження в SQLite, адаптивний інтерфейс;
- перевірено: 20 ручних перевірок у `docs/mvp.md` і 13 автоматичних тестів (`npm test`), усі пройдені;
- обмеження: застосунок запускається лише локально, немає відновлення пароля й підтвердження пошти, немає CSRF-токена (захист — `SameSite=Lax` і перевірка сесії), немає спільного доступу до завдань, нагадувань і файлів.
