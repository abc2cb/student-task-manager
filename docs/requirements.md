# Вимоги до Student Task Manager

## Призначення продукту

Student Task Manager — навчальний вебзастосунок для студента, який збирає завдання з кількох дисциплін в одному списку та допомагає контролювати дедлайни й статус виконання.

## Цільова аудиторія

Основний користувач — студент коледжу, який одночасно виконує роботи з кількох дисциплін і хоче бачити назву завдання, дисципліну, строк та поточний статус.

## Функціональні вимоги

### FR-01. Створення навчального завдання

Система повинна дозволяти студентові створити завдання, указавши його назву, дисципліну та дедлайн.

**Пріоритет:** високий.  
**MVP:** так.  
**Як перевірити:** заповнити назву, дисципліну й дедлайн, зберегти запис і переконатися, що нове завдання з'явилося у списку з уведеними даними.

### FR-02. Перегляд списку завдань

Система повинна відображати студентові список збережених завдань із назвою, дисципліною, дедлайном і статусом кожного запису.

**Пріоритет:** високий.  
**MVP:** так.  
**Як перевірити:** створити щонайменше два завдання та перевірити, що список показує обидва записи й чотири зазначені поля.

### FR-03. Редагування завдання

Система повинна дозволяти студентові змінити назву, дисципліну або дедлайн вже створеного завдання та зберегти оновлені дані.

**Пріоритет:** середній.  
**MVP:** так.  
**Як перевірити:** відкрити створений запис, змінити його дедлайн, зберегти та переконатися, що у списку відображається нове значення.

### FR-04. Видалення завдання

Система повинна дозволяти студентові видалити вибране завдання зі списку після підтвердження дії.

**Пріоритет:** середній.  
**MVP:** так.  
**Як перевірити:** вибрати тестовий запис, виконати видалення й підтвердити дію; запис не повинен залишитися у списку.

### FR-05. Зміна статусу виконання

Система повинна дозволяти студентові позначити завдання як виконане та відображати оновлений статус у списку.

**Пріоритет:** високий.  
**MVP:** так.  
**Як перевірити:** створити невиконане завдання, натиснути дію зміни статусу та переконатися, що запис має статус «Виконано».

## Нефункціональні вимоги

### NFR-01. Відображення на вузькому екрані

Основна сторінка продукту повинна відображатися у viewport шириною 320 CSS-пікселів без горизонтальної прокрутки основного вмісту.

**Пріоритет:** високий.  
**MVP:** так.  
**Як перевірити:** відкрити основну сторінку при ширині 320 px, порівняти `scrollWidth` і `clientWidth` та переконатися, що горизонтального переповнення немає.

### NFR-02. Збереження даних після перезавантаження

Після перезавантаження сторінки система повинна зберігати створене завдання з його назвою, дисципліною, дедлайном і статусом.

**Пріоритет:** середній.  
**MVP:** так.  
**Як перевірити:** створити тестове завдання, перезавантажити сторінку та переконатися, що запис і всі чотири значення залишилися доступними.

### NFR-03. Керування з клавіатури

Основні дії зі списком і формою повинні бути доступні з клавіатури, а поточний елемент фокусу повинен мати видимий індикатор.

**Пріоритет:** середній.  
**MVP:** так.  
**Як перевірити:** перейти між основними елементами клавішею Tab, виконати додавання або зміну статусу клавіатурою та перевірити видимий фокус.

## Висновок

Під час формування вимог задачі backlog перетворено на перевірювані результати для користувача. Найскладніше було відокремити функціональні дії від умов роботи системи та додати до кожної вимоги конкретну перевірку. Такий список дає основу для планування реалізації й перевірки MVP Student Task Manager.
