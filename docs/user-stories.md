# User stories програмного продукту

## Загальна інформація

**Назва продукту:** Student Task Manager.

**Основний актор:** студент коледжу.

**Додаткові актори:** відсутні. MVP розрахована на одного студента, який веде власний список навчальних завдань.

**Мета:** описати потреби студента для основних функцій MVP та визначити короткі, перевірювані умови приймання.

## Функції MVP та відповідні вимоги

| Функція MVP | User story | Пов’язана вимога |
| --- | --- | --- |
| Створення навчального завдання | US-01 | FR-01 |
| Перегляд списку завдань | US-02 | FR-02 |
| Редагування завдання | US-03 | FR-03 |
| Видалення завдання | US-04 | FR-04 |
| Зміна статусу виконання | US-05 | FR-05 |

## US-01. Створення навчального завдання

**User story:** як студент, я хочу додати навчальне завдання з назвою, дисципліною та дедлайном, щоб зберегти його в єдиному списку й контролювати строк виконання.

**Критерії приймання:**

- Після збереження нове завдання з’являється у списку.
- У записі відображаються введені назва, дисципліна та дедлайн.

**Пріоритет:** високий.

**Пов’язана функція MVP:** створення навчального завдання.

**Пов’язана вимога:** FR-01.

## US-02. Перегляд списку завдань

**User story:** як студент, я хочу переглядати список усіх навчальних завдань, щоб бачити актуальний обсяг роботи та найближчі строки.

**Критерії приймання:**

- Після створення двох завдань обидва записи відображаються у списку.
- Біля кожного запису показано назву, дисципліну, дедлайн і статус.

**Пріоритет:** високий.

**Пов’язана функція MVP:** перегляд списку завдань.

**Пов’язана вимога:** FR-02.

## US-03. Редагування завдання

**User story:** як студент, я хочу редагувати назву, дисципліну або дедлайн створеного завдання, щоб виправляти помилкову чи застарілу інформацію.

**Критерії приймання:**

- Користувач може змінити одне або кілька полів уже створеного завдання.
- Після збереження у списку відображаються оновлені значення.

**Пріоритет:** середній.

**Пов’язана функція MVP:** редагування завдання.

**Пов’язана вимога:** FR-03.

## US-04. Видалення завдання

**User story:** як студент, я хочу видаляти непотрібне завдання, щоб у списку залишалися лише актуальні записи.

**Критерії приймання:**

- Перед видаленням система просить підтвердити дію.
- Після підтвердження видалений запис більше не відображається у списку.

**Пріоритет:** середній.

**Пов’язана функція MVP:** видалення завдання.

**Пов’язана вимога:** FR-04.

## US-05. Зміна статусу виконання

**User story:** як студент, я хочу позначати завдання виконаним, щоб відрізняти завершену роботу від поточної.

**Критерії приймання:**

- Користувач може змінити статус завдання з «Не виконано» на «Виконано».
- Після зміни у списку відображається статус «Виконано».

**Пріоритет:** високий.

**Пов’язана функція MVP:** зміна статусу виконання.

**Пов’язана вимога:** FR-05.

## Висновок

Для Student Task Manager визначено студента основним актором і створено п’ять user stories для функцій MVP. Кожна історія містить роль, конкретну дію та користь для користувача, а також два перевірювані критерії приймання. Для всіх історій визначено пріоритет і встановлено зв’язок із відповідною функцією MVP та функціональною вимогою FR-01–FR-05.
